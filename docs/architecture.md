# Архитектура решения: AI-помощник по бизнес-контексту Меридиан

Решение разработано в рамках Хакатона **SBER Digital Reporting (Кейс 2)** командой из 5 участников.
Данный документ описывает архитектурный контур, оркестрацию агентов (Deep Agents), взаимодействие с LLM (GigaChat API) и поисковым движком RAG.

---

## 1. Концепция и ключевые ограничения

1. **Ключевое ограничение:** 1 поток GigaChat API на команду.
2. **Объём данных:** 3 258 документов, 18 банковских продуктов (P701–P718), 1 304 вложения 10 форматов.
3. **Оптимизация задержки и токенов:** Вместо длинной цепочки из 4–5 агентов (которая заняла бы 15–25 секунд) используется архитектура **ровно из 2 вызовов LLM**:
   - **Вызов 1 (GigaChat Lite):** Router-агент (извлечение метаданных, фильтрация, query rewrite).
   - **Локальный этап (без LLM):** Гибридный RAG-поиск (Vector + BM25 + RRF) + Cross-Encoder реранкер + чтение вложений.
   - **Вызов 2 (GigaChat Max):** Answer-агент (строго заземлённый ответ с цитатами `[slug]`).

```mermaid
graph TD
    User([Пользователь]) -->|Вопрос| Router[Router-агент: GigaChat Lite]
    Router -->|JSON: product_code, slug, need_attachment, rewrite| MetaFilter[Metadata-фильтрация]
    MetaFilter -->|Сужение до 10-30 документов| HybridSearch[Гибридный поиск: Vector e5-base + BM25]
    HybridSearch -->|Топ-20 кандидатов| RRF[RRF Fusion k=60]
    RRF --> Reranker[Cross-Encoder Reranker]
    Reranker -->|Топ-5 документов| AttachFetch[Enricher / Чтение вложений]
    AttachFetch -->|Контекст + Вложения| AnswerAgent[Answer-агент: GigaChat Max]
    AnswerAgent -->|Ответ + Цитаты [slug]| Response([Пользовательский интерфейс])
    Reranker -.->|Score + Связи| GraphViz[Pyvis Граф Релевантности]
```

## 2. Модули Участника 4 (Agent Engineer)

### 2.1 Клиент GigaChat API (`llm/gigachat_client.py`)
- **Rate-Limiting (1 поток):** Реализован потокобезопасный `threading.Lock` и `asyncio.Lock`, исключающий параллельные вызовы к API и ошибки 429.
- **Retry и Backoff:** Экспоненциальный откат (exponential backoff) при сетевых сбоях и таймаутах.
- **Модели:**
  - `GigaChat` (Lite) — для быстрой классификации и извлечения параметров (температура 0.1, ~500 in / 200 out токенов).
  - `GigaChat-Max` — для генерации фактологических ответов (температура 0.2, контекст до 32K токенов).
  - `GigaChat-Pro` / `Ultra` — резервные модели.
- **Автономный Mock-режим:** Если ключ `GIGACHAT_CREDENTIALS` не задан, клиент работает локально на базе каталога продуктов и правил, обеспечивая независимое тестирование без расхода квоты.

### 2.2 Router-агент (`agents/router_agent.py`)
- **Вход:** Вопрос пользователя на естественном языке.
- **Промпт:** `agents/prompts/router_system.txt` со справочником всех 18 продуктов банка.
- **Выходные поля (JSON):**
  - `product_code`: Код продукта (`P701`..`P718`) или `null`.
  - `product_name`: Название продукта (например, «Искра», «Росинка»).
  - `section`: Направление бизнеса (например, «Ежедневные расчёты», «Накопления»).
  - `owner`: Команда-владелец (например, «Команда Пульс»).
  - `slug`: Уникальный идентификатор страницы документа (если упомянут).
  - `doc_type`: Тип документа (`passport`, `architecture`, `sla` и т.д.).
  - `need_attachment`: Булев флаг необходимости обращения к файлам-вложениям.
  - `query_rewrite`: Очищенный от «воды» поисковый запрос.
- **Отказоустойчивость:** Многоуровневый парсер JSON (снятие markdown-блоков, исправление хвостовых запятых, сопоставление по справочнику продуктов).

### 2.3 Answer-агент (`agents/answer_agent.py`)
- **Вход:** Запрос пользователя + топ-5 документов от Reranker + текст вложений.
- **Промпт:** `agents/prompts/answer_system.txt`.
- **Правила генерации:**
  - **Нулевая толерантность к галлюцинациям:** Ответ формируется СТРОГО по переданному контексту. При нехватке данных выдаётся стандартное сообщение об отсутствии сведений.
  - **Табличные данные:** Таблицы (semicolon, tsv, markdown) сохраняются целиком без чанкинга, что предотвращает искажение строк и колонок.
  - **Цитирование (citations):** Каждое утверждение размечается слагом источника `[slug]`.
  - **Извлечение цитат:** Модуль автоматически парсит список использованных источников для UI.

### 2.4 Deep Agents Pipeline (`agents/pipeline.py`)
- Реализация фабрики `create_deep_agent` согласно концепции Deep Agents.
- Инкапсуляция роли, системного промпта, модели, инструментов и состояния `AgentState`.
- Синхронное (`execute`) и асинхронное (`aexecute`) выполнение.

### 2.5 Оркестратор (`agents/orchestrator.py`)
- Центральная точка входа, связывающая:
  `RouterAgent -> SearchEngine -> AttachmentEnricher -> AnswerAgent`.
- **Полная изоляция:** Поддерживает как реальный модуль поиска Участника 3 (`rag/search.py`), так и независимый `StandaloneSearchEngine`.
- **Генерация данных для графа (Pyvis):** Формирует структуры `graph_nodes` и `graph_edges` с цветовым кодированием по продуктам и весами рёбер, равными reranker score (для отображения Участником 5).
