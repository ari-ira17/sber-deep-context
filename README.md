# SBER Deep Context: Интеллектуальный помощник по бизнес-контексту «Меридиан»

Данный проект разработан в рамках хакатона SBER Digital Reporting (Кейс 2).
Решение представляет собой систему интеллектуального поиска и генерации ответов по корпоративной базе знаний «Меридиан», основанную на архитектуре Deep Agents, гибридном RAG (LanceDB + Cross-Encoder) и интеграции с GigaChat API.

---

## Архитектурные особенности и оптимизация

1. **Оптимизация обращений к GigaChat API**
   Архитектура пайплайна сведена к двум вызовам LLM для каждого запроса:
   `Вопрос` -> `Router (GigaChat Lite)` -> `Гибридный RAG + Reranker (локально)` -> `Answer (GigaChat Max)`
   Это сокращает время генерации ответа до 5–8 секунд и минимизирует риск возникновения ошибок 429 (Too Many Requests) при использовании однопоточного API.

2. **Обработка документации без чанкинга**
   Страницы базы знаний хранятся и обрабатываются целиком. Это предотвращает разрыв контекста при обработке сложных таблиц (TSV, Markdown) и фрагментированного кода.

3. **Предварительная фильтрация по метаданным**
   Маршрутизатор извлекает код продукта (P701–P718) и направление, что позволяет сузить пространство векторного поиска с 3 258 документов до 10–30 наиболее релевантных записей.

4. **Интерактивная визуализация релевантности**
   Реализовано построение графа связей между запросом и найденными документами с использованием библиотеки Pyvis (цветовое кодирование продуктов и отображение весов от реранкера).

## Структура проекта

```text
sber-deep-context/
├── llm/                       # Клиент GigaChat API (однопоточный лок, retry backoff)
├── agents/                    # Логика агентов
│   ├── router_agent.py        # Маршрутизатор: классификация и фильтрация (GigaChat Lite)
│   ├── answer_agent.py        # Генератор ответов: формирование ответа с цитированием [slug]
│   ├── pipeline.py            # Конвейер Deep Agents
│   ├── orchestrator.py        # Сквозной оркестратор и генерация графа Pyvis
│   └── prompts/               # Системные промпты агентов
├── app/                       # Веб-сервер FastAPI и HTMX-шаблоны
├── rag/                       # Модули поиска: LanceDB, BM25, RRF и Cross-Encoder
├── scripts/                   # Вспомогательные скрипты для инжеста и тестирования
├── docs/                      # Архитектурная документация и материалы для защиты
├── tests/                     # Модульные и интеграционные тесты
├── results/                   # Результаты прогона калибровочных вопросов
└── requirements.txt           # Зависимости проекта
```

## Развертывание и запуск

### 1. Клонирование репозитория
Склонируйте исходный код проекта на локальную машину:
```bash
git clone <URL_репозитория> sber-deep-context
cd sber-deep-context
```

### 2. Установка зависимостей
Рекомендуется использовать виртуальное окружение:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Настройка переменных окружения
Создайте конфигурационный файл `.env` в корневой директории:
```env
# Авторизационные данные GigaChat API
GIGACHAT_CREDENTIALS=ваш_токен_авторизации
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_VERIFY_SSL_CERTS=false

# Модели
GIGACHAT_MODEL_LITE=GigaChat
GIGACHAT_MODEL_MAX=GigaChat-Max
```
> **Примечание:** Если переменная `GIGACHAT_CREDENTIALS` не задана, система автоматически переходит в автономный Mock-режим, позволяющий тестировать пайплайн без обращения к внешнему API.

### 4. Подготовка базы данных
При первоначальном клонировании векторная база данных пуста. Для загрузки документов из `data/dataset_with_vectors.json` и инициализации полнотекстовых индексов (FTS BM25) выполните команду:
```bash
python scripts/ingest.py
```
**ВАЖНО:** Для корректной работы со ссылками на вложения (изображения, исходный код) директория `meridian_hackathon_knowledge_base` должна располагаться строго **в корне проекта**.

### 5. Запуск веб-сервера
```bash
uvicorn app.main:app --reload --port 8017
```
Сервер будет доступен по адресу: http://localhost:8017

### 6. Запуск с помощью Docker
Для быстрого развертывания проекта в изолированной среде вы можете использовать Docker Compose:
```bash
docker-compose up --build
```
> **Примечание:** База данных (`data/`) и база знаний (`meridian_hackathon_knowledge_base/`) автоматически пробрасываются в контейнер. Загруженные файлы из песочницы будут сохраняться между перезапусками. Сервер будет доступен по тому же адресу: http://localhost:8017
